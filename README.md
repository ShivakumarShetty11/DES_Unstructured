# Dhara Toolkit — Unstructured Data Catalog

PDF extraction · metadata catalogue · semantic vector search · MCP endpoint.

Built for ingesting, cataloguing, and querying unstructured PDF documents (government circulars, policy documents, research papers, scanned files) with AI-powered extraction and search.

---

## Features

- **Two-step ingest workflow** — extract first, review the preview, push to catalogue only when satisfied
- **Dual-mode PDF extraction** — pypdf for digital PDFs; Claude Vision OCR fallback for scanned/image-based PDFs
- **AI summary** — auto-generated by Claude (`claude-sonnet-4-6`); extractive fallback if API key is absent
- **Full text storage** — extracted text stored in SQLite alongside metadata
- **Original PDF storage** — uploaded PDFs saved to `uploads/`; downloadable via the catalogue
- **Vector search** — text chunked and stored in ChromaDB (cosine similarity)
- **Catalogue UI** at `/catalogue` — split query panel + dataset stream, opens in new tab
- **Hierarchical filtering** — sub-category list updates dynamically when a category is selected
- **Search priority** — category and sub-category weighted highest in keyword scoring
- **Download** — original PDF or full JSON (metadata + extracted text) per dataset
- **REST API** for all datasets
- **MCP endpoint** — connect Claude Code CLI directly to the catalogue (HTTP JSON-RPC transport)

## Local Setup

### 1. Create virtual environment

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
pip install -r requirements.txt
```

### 3. Configure `.env`

```env
APP_NAME=Dhara Toolkit
ANTHROPIC_API_KEY=sk-ant-...
```

`ANTHROPIC_API_KEY` is required for AI summaries and Claude Vision OCR. Without it the system falls back to extractive summarisation and cannot process scanned PDFs.

### 4. Start server

```powershell
uvicorn app.main:app --reload --port 8000
```

### 5. Open in browser

| Page | URL |
|---|---|
| Ingest | http://localhost:8000/ |
| Catalogue | http://localhost:8000/catalogue |
| API index | http://localhost:8000/api/ |
| MCP info | http://localhost:8000/mcp |

## Ingest Workflow

```
Upload PDF / paste URL
        │
        ▼
POST /api/datasets/extract
  ├─ save PDF to uploads/
  ├─ pypdf text extraction
  └─ Claude Vision OCR (fallback for scanned PDFs)
        │
        ▼
Preview — AI summary + extracted text + stats
        │
   satisfied?
        │ yes
        ▼
POST /api/datasets/push
  ├─ store metadata + full text in SQLite
  └─ chunk text → store in ChromaDB
        │
        ▼
Dataset visible in Catalogue
```

## REST API

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/health` | Health check |
| `GET` | `/api/` | API index with all endpoint URLs |
| `POST` | `/api/datasets/extract` | Extract text + summary (no storage) |
| `POST` | `/api/datasets/push` | Store extracted document in DB + vector store |
| `GET` | `/api/datasets` | List / search datasets (`?q=&category=&sub_category=`) |
| `GET` | `/api/datasets/{id}` | Get single dataset (metadata only) |
| `GET` | `/api/datasets/{id}/download` | Download full JSON (metadata + extracted text) |
| `GET` | `/api/datasets/{id}/document` | Download original uploaded PDF |
| `POST` | `/api/datasets/semantic-search` | Vector similarity search |

### Extract — `POST /api/datasets/extract`

`multipart/form-data` fields:

| Field | Required | Notes |
|---|---|---|
| `title` | yes | |
| `category` | yes | |
| `sub_category` | yes | |
| `document_type` | yes | |
| `tags` | no | JSON array string e.g. `["policy","incentive"]` |
| `issuing_department` | no | |
| `policy_year` | no | |
| `document_url` | no | Used if no file uploaded |
| `source_language` | no | |
| `file` | no | PDF file upload |

At least one of `file` or `document_url` must be provided.

**Response** includes `extracted_text`, `text_preview`, `summary`, `estimated_chunks`, `file_name`, and all metadata fields. Nothing is saved except the raw PDF to `uploads/`.

### Push — `POST /api/datasets/push`

JSON body — send the full response from `/extract` back unchanged:

```json
{
  "title": "...",
  "category": "...",
  "sub_category": "...",
  "document_type": "...",
  "tags": ["..."],
  "extracted_text": "<full text>",
  "summary": "<ai summary>",
  "file_name": "abc123_document.pdf"
}
```

### List / Search — `GET /api/datasets`

Response includes a `filters` object for building UI dropdowns:

```json
{
  "count": 42,
  "datasets": [...],
  "filters": {
    "categories": ["IT & Technology", "Land & Revenue"],
    "sub_categories": ["Data Centers", "Land Acquisition"],
    "category_map": {
      "IT & Technology": ["Data Centers", "Software Policy"],
      "Land & Revenue": ["Land Acquisition"]
    }
  }
}
```

Use `category_map` to populate sub-category options based on the selected category (hierarchical filtering).

### Semantic Search — `POST /api/datasets/semantic-search`

```json
{ "query": "data centre incentives", "category": "IT & Technology", "limit": 8 }
```

## MCP Integration

The MCP endpoint exposes catalogue tools over HTTP JSON-RPC (MCP protocol version `2024-11-05`).

> **Note:** The current transport is plain HTTP JSON-RPC, which is compatible with **Claude Code CLI** (`--transport http`). Claude Desktop requires the MCP Streamable HTTP transport (SSE-based) which is not yet implemented.

### Claude Code CLI

```bash
claude mcp add --transport http des-catalog http://localhost:8000/mcp
```

For the deployed Cloud Run service:

```bash
claude mcp add --transport http des-catalog https://des-unstructured-235956738573.europe-west1.run.app/mcp
```

### settings.json

```json
{
  "mcpServers": {
    "des-catalog": {
      "type": "http",
      "url": "http://localhost:8000/mcp"
    }
  }
}
```

### Available MCP Tools

| Tool | Description |
|---|---|
| `list_datasets` | List all ingested documents (metadata only) |
| `get_dataset(dataset_id)` | Full record including extracted text |
| `get_dataset_text(dataset_id)` | Extracted text only |
| `search_datasets(query)` | Keyword search (category-weighted, metadata only) |
| `semantic_search_datasets(query)` | Vector similarity search (chunks + metadata) |

## PDF Extraction Pipeline

| Stage | Library | When used |
|---|---|---|
| Primary | pypdf 4.x | All digitally-created PDFs (Word exports, government portals) |
| Fallback | Claude Vision (`claude-sonnet-4-6`) via pymupdf rendering | Scanned / image-based PDFs where pypdf returns < 80 chars |

Vision OCR renders each page at 150 DPI and processes up to 40 pages per document.

## Deployment — GCP Cloud Run

The app is deployed on Google Cloud Run via a Cloud Build trigger connected to the GitHub repository.

### Trigger substitution variables

| Variable | Value |
|---|---|
| `_AR_HOSTNAME` | `europe-west1-docker.pkg.dev` |
| `_AR_PROJECT_ID` | `data-unlock` |
| `_AR_REPOSITORY` | `cloud-run-source-deploy` |
| `_SERVICE_NAME` | `des-unstructured` |
| `_DEPLOY_REGION` | `europe-west1` |

### Important Cloud Run settings

- **Min instances: 1** — required to keep SQLite and ChromaDB state in memory between requests. Without this, a cold start resets all data.
- **No GCS volume mount** — SQLite and ChromaDB use file locking which is incompatible with GCS FUSE. Data is stored on the container's local filesystem.
- Pushing new commits to `main` triggers a fresh build (`--no-cache`) and redeploys automatically.
